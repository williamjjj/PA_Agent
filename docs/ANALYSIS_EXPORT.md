# 导出分析结果与过程（1.68.3）

顶部菜单 **导出分析** 可导出当前显示的分析，也可从下拉列表选择历史记录，或打开其他目录的分析 JSON。无需重新调用模型。

## 操作

1. 打开「导出分析」，确认记录的品种、周期和分析时间。
2. 勾选需要的环节，或点击「全部环节」「仅最终结论」「诊断与决策」。
3. 选择 ZIP、HTML、Markdown 或 JSON，点击「选择位置并导出」。
4. 保存后可点击「打开导出文件夹」。默认目录为应用数据目录下的 `exports`。

新一轮分析仍在运行时，导出窗口明确显示其状态，可先导出上一条已返回的记录；当前轮结束后重新打开窗口导出。导出过程在后台运行。原始分析记录保持原样，不能选择其路径作为导出目标。

## 可选择的环节

| 环节 | 内容 |
|---|---|
| 最终结论 | 市场诊断摘要、最终决策、风险说明 |
| 分析输入 | 实际送入分析的 K 线、指标及已保存的上级周期资料 |
| 阶段一 | 市场周期、方向、逐根 K 线判定、诊断节点等完整诊断 JSON |
| 策略选择 | 当时选择的策略文件名称、实际载入的参考经验 |
| 阶段二 | 决策条件、节点路径、最终节点、价格计划和已返回的走势预期 |
| 外部资讯 | 选入本次分析的资讯、来源、查询时间 |
| 追问 | 对应分析的追问、回答及模型实际返回的过程文本 |
| 技术记录 | 两阶段提示词、完整模型返回、逐次请求与校验重试的返回内容 |

每份导出都包含分析元数据、完成状态、异常信息和用量记录。密钥字段及当前配置中已知的密钥值会隐藏；完整应用配置、登录文件和其他分析记录不加入导出。

## 完整 ZIP

- `分析报告.html`：独立的可阅读报告，无需联网。技术明细可展开；用浏览器打印可另存为 PDF。
- `分析报告.md`：按环节组织的 Markdown 文档，保留结构化内容。
- `导出内容.json`：本次所选内容的完整结构化封装。
- `环节/`：每个选中环节独立的 JSON。
- `输入_K线.csv`：标准六列 OHLCV，时间升序，时间戳沿用记录中的 Unix 毫秒。
- `输入_K线与指标.csv`：保留序号、指标等附加列。
- `模型返回/`：各阶段已保存的回答与过程文本，便于单独查看。
- `manifest.json`：文件清单、大小和 SHA-256。

仅导出勾选的环节。选择「仅最终结论」时，提示词、K线和资讯等未勾选内容不会夹带在 ZIP 或 JSON 中。

## 失败、取消与旧记录

失败或取消的记录保留已完成的阶段，并明确标注未完成内容。本版开始保存正常调用及校验重试的逐次返回；阶段二中途取消时，也保留已经完成的阶段一结果。

旧记录没有保存的逐次请求、未执行的环节、服务没有返回的文本会标记为缺失。导出不会补造这些内容。逐次请求时间是程序收到该次返回的时间。

## 命令行与 harness

```text
pa-agent-cli export --record "分析记录.json" --output "完整分析.zip"
pa-agent-cli export --record "分析记录.json" --output "结论.html" --sections summary
pa-agent-cli export --record "分析记录.json" --output "诊断与决策.json" --sections summary,stage1,stage2
```

可用环节 ID：`summary,input,stage1,routing,stage2,information,followups,technical`。
输入也可以是 `analyze --output` 保存的结果 JSON。追问从同名 `.followups.jsonl` 文件读取。命令行默认拒绝覆盖已有文件，确认需要替换导出文件时可加 `--overwrite`；原始输入文件始终不能被覆盖。

AlphaGPT 研究窗口原有的「导出完整结果」继续用于因子、回测与公式搜索结果；本次新增的是 PA 两阶段分析的统一导出入口。
