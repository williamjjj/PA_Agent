# 桌面版 1.68.4：3000 根 K 线性能优化

本次改动位于 `codex/desktop-performance-20261106`，基于桌面版 1.68.3
（`a1830e35c3f9736c2f6cea3f31a98a5914aa1519` 的前缀 `a1830e3`）。
`main` 继续承载 Vercel 网页版。本分支保留 `vercel.json` 中的
`git.deploymentEnabled: false`，不会为桌面代码创建 Vercel 部署。

## 改动

- 获取行情直接进入后台请求，去掉按钮中的重复联网探测和 1.5 秒固定等待。
- 分析复用正在获取的行情，避免同一数据源重复排队；获取期间提交按钮锁定。
- 新增“取消任务”和当前步骤、等待秒数。获取超过 35 秒会取消并提示检查数据源。
  TradingView 请求有 30 秒总预算，取消时直接中断套接字，不等待关闭握手。
- 停止刷新、切换品种、取消分析时不在界面线程等待后台任务。线程运行结束后再回收；
  关闭窗口时等待后台退出期间仍保持事件循环。
- 全部 K 线保存在同一绘图对象内，按 128 根缓存绘图指令；只重建变化的部分。
  K 线编号随可见区域生成，缩到全历史时最多显示 150 个编号。横向拖动可查看全部历史。
- 首次分析的模型依赖加载进入后台准备阶段。Codex、WorkBuddy、Hermes 等本地 agent
  在运行期间显示已等待时间及是否已收到输出。
- Windows 本地 agent 清理时等待其子进程真正退出，再删除临时请求文件。

分析范围、指标预热、发送给模型的 K 线表、分析记录和导出内容保持完整。
新增后台处理不改变模型、策略、因子、回测与数据源配置。

## 同机对比

2026-11-06，Windows x64，CPython 3.12.13，Qt 6.12.0。
同一脚本在独立的旧版工作树和新版工作树中执行；各自使用隔离运行目录。
每次使用同一组 3000 根合成 K 线，首绘后连续更新 50 次，每次仅改变最新收盘价。
表中耗时包含事件处理。界面停顿以 10 毫秒定时器的实际间隔测量。

| 测量项 | 1.68.3 | 1.68.4 |
| --- | ---: | ---: |
| 图表首次绘制 | 628.494 ms | 59.593 ms |
| 后续刷新中位耗时 | 1166.834 ms | 10.148 ms |
| 后续刷新 P95 | 1407.872 ms | 11.845 ms |
| 获取按钮返回 | 1589.364 ms | 3.921 ms |
| 获取至图表就绪 | 2740.997 ms | 434.604 ms |
| 取消获取返回 | 256.398 ms | 0.091 ms |
| 首次提交期间最大界面间隔 | 1919.716 ms | 46.504 ms |
| 后续两次提交期间最大界面间隔 | 881.701 / 901.981 ms | 36.776 / 44.732 ms |
| 50 次刷新后的进程工作集 | 155.69 MiB | 93.24 MiB |
| 场景对象数（首绘 / 25 次 / 50 次） | 6020 / 6020 / 6020 | 43 / 43 / 43 |

获取测试人为设置预检查 80 ms、行情服务 300 ms；分析测试人为设置模型每阶段 150 ms。
这些值用于隔离本地界面开销，真实网络和模型生成时间由数据源、网络、模型决定。
模型等待时间仍计入界面显示，取消按钮可在此期间使用。

模型表格在两个版本中均为 348407 字符，SHA-256 完全一致：
`0255a80f3150789c3d7f6d55716e4636860f0ccd6c809d6ff72a245f937c2e8e`。
三次分析提交均保留 3000 根 K 线；测量结束时 Python 后台线程数均回到 1。
另做 500 次连续刷新：中位耗时 9.106 ms，P95 10.791 ms；场景对象始终为 43，
工作集从 92.47 MiB 到 93.36 MiB。该测试覆盖重复更新，尚未进行数小时连续运行测量。

原始结果见 [before.json](performance/1.68.4-before.json)、
[after.json](performance/1.68.4-after.json)、[500 次连续刷新](performance/1.68.4-endurance.json)。

```powershell

```

取消后的旧结果丢弃、指标预热、连接清理、本地 agent、两阶段分析及结果导出。
