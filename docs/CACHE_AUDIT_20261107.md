# 桌面版 1.68.6：Codex Fast 缓存核验

本次沿用 gpt-6-astra、max、Fast 和原 QQQ 5m 的 3000 根冻结快照。主网页分支不包含本次桌面修复。

## 已确认的事实

PA Agent 读取 Codex `turn.completed.usage.cached_input_tokens`。这个字段名称与 [Codex 官方事件定义](https://github.com/openai/codex/blob/main/codex-rs/exec/src/exec_events.rs)一致。

四个小规模真实请求均保持 Astra / max / Fast，并保留了原始 JSON：

| 运行 | 输入 token | Codex 原始缓存读取 | PA Agent 解析结果 |
|---|---:|---:|---:|
| 随机目录 1 | 22,754 | 12,416 | 12,416 |
| 随机目录 2 | 22,754 | 15,360 | 15,360 |
| 固定目录 1 | 22,738 | 7,296 | 7,296 |
| 固定目录 2 | 22,738 | 0（字段明确存在） | 0 |

因此 Fast 能命中缓存，也能明确返回零命中，当前 flat 字段解析没有漏算。固定目录的短请求也出现零值，目录变化不是唯一因素。

旧完整 Fast 运行保存了累计计数，但请求结束后清除了 CLI 原始事件，所以无法逐阶段回溯其原始字段。本次完整复测通过新版记录保存原始数字，核验它们与累计计数相等。

缓存复用要求匹配可复用前缀，并受可用缓存与请求路由影响；保持相同原始行情只是其中一个条件。缓存读取和缓存写入是不同计数。[OpenAI 缓存文档](https://developers.openai.com/api/docs/guides/prompt-caching)

## 修复

1. 不再把“没有提供缓存字段”和“明确返回 0”混为一谈。界面分别显示“未报告”和“0”；多阶段混合时显示已知下限及部分未报告状态。
2. 分析及追问记录保存 `usage_audit`，保留原始数字字段，包括输入、缓存读取、缓存写入、输出和推理 token。只保留用量，不保存 stderr 或任意诊断字段。
3. Codex 只以完成事件的用量为准，后续不完整诊断事件不会覆盖完整计数。
4. Codex 使用固定工作目录。每次请求的提示词和输出仍放在隔离临时目录并正常清理，移除模型上下文中不必要的随机目录变化。
5. 修复显式填写模型时重复传入 `--model` 导致 CLI 拒绝启动的问题。

没有修改分析模型、推理强度、3000 根输入、两阶段提示词或交易决策规则。额度减少与否由完整复测结果报告，不把固定目录本身描述为必然提高命中率。

## 验证与结果位置

63 项相关测试通过，覆盖明确零值、字段缺失、原始计数保留、不完整事件、跨阶段累计、追问累计、界面显示、请求文件清理、模型参数和原有分析导出。修改文件的执行错误级静态检查通过。

完整 3000 根复测的阶段用量、耗时和额度观察随桌面版 1.68.6 的验证附件交付。用户原始行情、完整分析内容、账户额度快照和本机配置保留在本地。
