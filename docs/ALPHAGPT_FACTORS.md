# AlphaGPT 因子：PA Web 第一阶段计算口径

实现：`pa_agent/web/quant.py`。来源：AlphaGPT 的六个基础因子，详见
[`third_party/AlphaGPT`](../third_party/AlphaGPT/README.md)。

本适配器的特征版本为 **`alphagpt-causal-v1`**。它是同一行情快照上的解释性
因子面板，不输出收益预测、回测业绩或交易指令。它更改了上游的时间处理和
归一化方式，**不能直接输入原有 AlphaGPT 已训练公式或权重**。

## 输入、方向与收盘边界

`compute_factors(frame: KlineFrame) -> dict` 只读取传入的不可变行情快照，不读取
个人凭据、不请求外部行情、也不读写数据库。PA 的 `bars` 从新到旧，适配器
反转为从旧到新计算，并按这个时间顺序输出 `series`。

仅接受 `closed=True` 且按快照采集时刻已经结束的 K 线；重复时间、次序错误、
时间重叠、非有限数、零/负价格、异常 OHLC 范围、负成交量均令整个计算失败，
不会自动修补或丢弃错误行。价格上限为 `1e12`，成交量上限为 `1e18`，与 CSV
导入限制一致。`as_of` 为最后一根 K 线结束时刻的 UTC 毫秒，序列 `time` 为
开盘时刻的 UTC 秒。月线使用下一个自然月的第一天计算结束时刻，而不是
固定 30 天。此结束时刻沿用 PA 周期定义，不代表已核实各交易所的实际收市时刻。

输出只包含 JSON 有限数或 `null`。空快照返回 `unavailable`；无效快照抛出
`ValueError`，上层应保留行情快照身份并显示计算不可用。

## 原始因子

记 `c/o/h/l/v` 为当前已收盘 K 线的收盘/开盘/最高/最低价及成交量，`t-1`
为紧邻周期的上一根，`mean20` 为最近 20 根已观测 K 线的收盘均值。

| ID | 原始 `value` | 预热与含义 |
|---|---|---|
| RET | `log(c[t]) - log(c[t-1])` | 首根为空；不把最后一根绕回首根。对数收益，不是百分数显示值 |
| LIQ | 若有历史数据应为 `clip(4 × liquidity / (fdv + 1e-6), 0, 1)` | 当前 `KlineFrame` 只有 OHLCV，全部为 `null`。不以当前流动性回填，不将缺失当零 |
| PRESSURE | `tanh(3 × (c-o) / (h-l+1e-9))` | 范围约 [-1,1]；蜡烛实体与振幅的形态代理，不是真实买卖订单流 |
| FOMO | `clip(g[t] - g[t-1], -5, 5)`，其中 `g[t]=(v[t]-v[t-1])/(v[t-1]+1)` | 前两根为空；需要连续三根，名字沿用上游，不证明投资者心理 |
| DEV | `(c - mean20) / mean20` | 前 19 根为空，均值不补零。数值 0.05 表示相对均价高 5% |
| VOL | `log(1+v)` | 合法零成交量得到 0；源可能提供手数、合约数、币数量或 tick 数，不可跨来源直接比较 |

`change` 是当前原始值减上一根原始值。任一值为空，或两个时间区间不相邻时，
变化值也为空。

## 因果归一化与历史分位

每根时点只使用当前和过去数据。滚动窗口最多为**最近 60 根已观测 K 线**，
其中至少需要 20 个非空因子值。窗口不足时仍可显示已计算的原始值，但
`normalized` 和 `percentile` 为空，状态为 `warming_up`。

所有可计算因子统一使用下面的额外归一化字段。PRESSURE 的 `value` 保留原始
有界 `tanh` 数值，`normalized` 是另行计算的历史相对位置；它并不等于上游
直接放入特征向量的 PRESSURE。这个区分也是不能直接复用旧训练公式的原因。

```text
center = median(window 的有效原始值)
MAD = median(abs(value - center))
normalized = clip((current - center) / (MAD + 1e-6), -5, 5)
percentile = 100 × (低于当前值的数量 + 0.5 × 等于当前值的数量) / 有效数量
```

窗口包含当前点，因此历史分位是该窗口内的位置，不是样本外概率。相等值采用
中间秩；恒定序列归一化为 0，分位为 50%。不同因子没有汇总成总评分，也不
把高分位解释为上涨概率。RET 的第 21 根、FOMO 的第 22 根、DEV 的第 39 根
才首次可能得到 20 个有效值；VOL 的第 20 根首次可能满足。缺口会延长预热。

## 时间间隔与市场日历

适配器检查当前开盘时刻是否紧接上一根结束时刻。遇到不连续的时间间隔，RET
不跨过边界计算；FOMO 要等连续三根重新形成。任何因子的 `change` 不跨间隔
计算；原始 K 线不插值、不填充、不增加虚构观测。

`KlineFrame` 尚无交易日历，周末、午休、停牌与数据遗漏可能表现为相同的时间
间隔。因此输出 `calendar_unverified`，明确“无法区分休市与缺失数据”，不直接
断言缺少行情。DEV 及归一化窗口继续按已经观测到的 K 线计数；它们表示最近
N 次观察，不能解释为连续 N 个自然周期。这也避免 A 股周末令 20 日均值永远
无法预热。连续市场的覆盖率应由行情提供方另行核验。

## 状态与验证

每个因子独立返回 `ready`、`warming_up` 或 `unavailable` 和原因。顶层仅在
全部因子就绪时为 `ready`，存在可用原始值但不完整时为 `partial`，没有任何
可用值时为 `unavailable`。因为只有 OHLCV 时 LIQ 始终缺失，正常快照顶层
为 `partial`；界面应展示可用的五个因子和流动性缺失原因。

测试覆盖已知公式向量、首段预热、末端追加/未来改写不改变历史点、60 根窗口
边界、常量与零量、数值极端、缺口/周末、自然月结束、坏数据与未收盘拒绝，
以及严格 JSON 序列化。它们验证数值与因果性，不验证这些因子的投资效果。
