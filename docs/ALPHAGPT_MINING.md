# 第三阶段：有预算、可恢复的公式研究

计算入口为 `pa_agent/web/mining.py` 的 `MiningSession`；公式解释器位于
`pa_agent/web/formula.py`。这是一种有预算的 CPU 公式搜索，使用前两阶段的
因果特征与研究成交模型，不导入旧 AlphaGPT 的 Transformer、整数词表、训练
权重或交易执行模块。

## 版本与搜索范围

| 对象 | 版本 |
|---|---|
| 搜索引擎 | `pa-rpn-search-v1` |
| 公式词表 | `pa-causal-rpn-v1` |
| 特征 | `alphagpt-causal-v1` |
| 成交研究引擎 | `pa-research-v1` |
| 检查点 | `pa-mining-checkpoint-v1` |

公式只读取五个基础因子的因果归一化序列：`RET`、`PRESSURE`、`FOMO`、`DEV`
和 `VOL`。历史流动性缺失的 `LIQ` 不参与搜索。每个候选最多 15 个 token，
运算树深度最多 3；输入叶子的深度为 0。每个任务最多 128 个候选、5000 根
已收盘 K 线。数据范围、连续现货、费用、分段、下一根开盘成交、段末退出等
规则均继承 [历史研究说明](ALPHAGPT_BACKTEST.md)。

公式采用命名 token 的逆波兰序列。例如：

```text
["RET", "MEAN3", "VOL", "DELAY1", "SUB"]
→ SUB(MEAN3(RET), DELAY1(VOL))
```

表达式字符串仅用于展示，不执行 Python `eval`。未知 token、旧整数公式、
操作数不足、多余结果、超长或超深公式均拒绝。

| 算子 | 定义 |
|---|---|
| `ADD/SUB/MUL/DIV` | 两个同时间点序列的加、减、乘、除；先入栈为左操作数 |
| `NEG/ABS/SIGN` | 取负、绝对值、符号；SIGN 为 -1/0/1 |
| `DELAY1` | 只读取上一根，首根为空，不循环绕回末尾 |
| `MEAN3` | 当前及之前两根的算术平均 |
| `DECAY` | 最近三根由旧到新按 1/6、2/6、3/6 加权 |
| `MAX3` | 当前及之前两根的最大值 |

任一所需输入为空，输出也为空。三根窗口必须完整，不能跳过缺值后凑够三根。
除数绝对值不超过 `1e-12` 时留空；非有限运算结果留空，不替换为零或无限大。
所有时间算子只读取当前及过去，后续追加或改写未来不会改变历史公式值。

## 配置、确定性与恢复

`MiningConfig` 不允许额外字段：

| 字段 | 默认 | 范围/含义 |
|---|---|---|
| `seed` | 42 | 整数 0～2³¹−1 |
| `trials` | 32 | 整数 8～128，计划候选数 |
| `max_seconds` | 60 | 整数 10～120，任务累计计算时间预算，由 Worker 执行 |
| `research` | `ResearchConfig()` | 分段、方向、阈值分位、资金、费用和滑点配置 |
| `min_trades` | 1 | 整数 1～20，候选训练段最少完成交易数 |

`research.factor` 是第二阶段的单因子选择字段，在挖掘中不参与计算；产物
明确记录 `ignored_research_fields=["factor"]`。最终研究结果的信号字段为
`FORMULA`，不会把选出的组合表达式误标成默认 `DEV`。

前五个候选依次是五个基础因子。其余候选由词表版本、种子和候选索引的
SHA-256 值初始化局部随机数生成器，再生成有界语法树。某个候选不依赖之前
的收益、候选是否有效、全局随机数状态或机器时间。完全相同的数据、配置、
版本和候选范围会得到相同结果；最高评分相同时选择候选索引较小者。

`MiningSession` 的计算接口如下：

```python
session = MiningSession(chart, MiningConfig(...), checkpoint=stored_checkpoint)
while not session.done:
    # Worker 在每一步前后检查取消、累计时间、租约和任务状态。
    checkpoint = session.step()  # 恰好评估一个候选
    # Worker 持久化 checkpoint；不要只保存在浏览器内存。
result = session.finish()        # 全部候选完成后才计算获选者的样本外结果
```

计算类不自己创建线程、不访问网络或数据库。Worker 负责累计预算、并发限制、
取消、心跳、检查点持久化和恢复；重新启动不应获得一份新的完整时间预算。
每一步在固定候选大小与数据量内完成，以便 Worker 在候选之间检查取消/超时。
未完成全部候选时，`finish()` 拒绝生成产物，保留的只有训练段检查点。超时或
取消后不能把部分搜索自动发布成完成结果。

检查点包含数据指纹、训练前缀指纹、完整配置及配置摘要、计算版本、下一候选
索引、拒绝数量、最多十个不同公式的训练排名及当前领先者。排名不含验证或
测试指标。检查点校验和用于发现损坏；恢复时还核验数据、配置和各版本。
运行层另行保存内容版本/代码摘要并在恢复时核验，避免升级代码后按旧检查点
静默继续。相同检查点恢复后的候选顺序和最终结果与不中断运行一致。

## 候选资格与选择严格只用训练段

候选解释器只收到训练前缀的特征数组。候选至少须有 60 个有效训练值，由
这些值拟合固定入场/退出分位阈值，且两阈值不能重合。接着只对训练段运行
扣除手续费和滑点的成交模拟，并要求至少 `min_trades` 笔完成交易。

```text
fitness = 训练段 total_return − 0.5 × 训练段 max_drawdown
```

指标采用比例小数，回撤为非负数。该目标不声称是经济上最合适的效用函数，
只是公开、固定、可重放的选择规则。未满足资格或出现无效训练算术的候选
计为拒绝，不用样本外数据补足。相同公式重复生成会消耗一次计划尝试，但
排名表仅保留该公式的较早候选。

**样本外数据既不参与评分，也不参与候选资格判断。** 即使某公式在验证或
测试段会遇到零除或大量空值，也不能据此在搜索中淘汰它。全部搜索结束后
先冻结训练排名第一的公式，再计算它的完整因果序列和三段研究结果。

获选公式的训练阈值会再次核对；复核不一致则失败，不替换成另一个候选。
样本外空值保留为空，未产生有效信号时不假造交易，并以 `formula_quality`
记录各段有效/空值数量。结果不好或没有样本外交易也不会触发“换第二名”或
重新搜索。固定的三档费用情景沿用第二阶段，只用于结果检查，不用于选优。

如果全部候选不合格，任务明确失败而不是返回一个虚构公式。获选候选也可能
训练收益为负；“获选”仅表示已尝试候选中训练目标最高，不表示可交易优势。

## 产物与解释限制

计算产物包含：

- `formula`：命名 tokens、展示表达式、内容 ID/摘要、各版本、训练前缀和来源
  数据指纹、种子、完整配置、候选索引；运行层补充代码摘要与任务身份。
- `selection`：训练目标、评分、实际尝试数、拒绝数、计划数量、完成状态及
  最多十个公式的训练排名。
- `research_result`：获选公式在训练、验证和测试上的完整权益、成交账本、
  买入持有基准、成本敏感性、分段与因子有效值数量。
- `warnings`：训练搜索偏差、样本外使用方式、计算模型限制。

训练表现经过多次候选筛选，含有额外搜索选择偏差，不能作为样本外证据。
没有使用测试段选优，并不消除反复查看结果后人工改变种子、配置、数据范围
带来的偏差。完整排名、尝试次数和配置应随结果保存；只展示最好的一条会
隐藏试验数量。小样本、固定滑点和 OHLCV 成交模型也无法证明实盘容量。

本阶段不输出收益承诺、自动下单或私钥操作。旧 AlphaGPT 更大规模的训练、
跨标的验证和 GPU 工作负载需要另外设计、评估和版本化，不能把本 CPU 搜索
描述成已经执行了那些训练。

## 数值与因果性验证

测试覆盖各算子的已知向量、预热与空值、除零/溢出、无效或旧格式公式拒绝、
程序长度和深度上限、种子重现、未来改写/追加不改变历史值、只对训练段运行
候选模拟、检查点恢复等价、样本外变化不改变资格/排名/阈值、损坏或异源检查点
拒绝、未完成搜索不生成产物、全部候选不合格，以及配置预算边界。第二阶段
原有的 45 项研究测试继续通过。此类验证证明计算契约，不证明公式投资效果。

## 任务接口、运行与隔离

`POST /api/mining/jobs` 接受 `dataset_id`、`config` 与 `idempotency_key`。
同一账户使用相同标识和内容重复提交，返回原任务；同一标识对应不同内容时
拒绝。提交只写入数据库，不在 FastAPI 请求中运行搜索。所有私有接口沿用
会话、来源校验和跨标签页账户身份检查，客户端不能指定其他账户作为所有者。

- `GET /api/mining/status`：兼容当前计算版本且心跳新鲜的 Worker 数量和限额。
- `GET /api/mining/jobs?offset=0`：当前账户的任务摘要，每页 25 条。
- `GET /api/mining/jobs/{id}`：状态和已保存结果，仅读取，不重新计算。
- `POST /api/mining/jobs/{id}/cancel`：排队任务立即取消；运行任务先标记取消请求。
- `POST /api/mining/jobs/{id}/retry`：失败、取消或超时后显式创建新任务，保留原记录；
  新请求仍须使用幂等标识。它不是伪造旧任务成功或静默重置预算。
- `DELETE /api/mining/jobs/{id}`：仅删除当前账户已结束的任务。
- `GET /api/mining/jobs/{id}/export`：导出任务、公式、结果和原始数据，不包含租约令牌。

新表 `web_mining_jobs` 与 `web_mining_workers` 在连接时创建。任务对数据集使用
账户/数据集组合外键；任务存在时原数据集无法删除。每账户最多 3 个活动任务、
50 个总任务，最多一个任务处于执行中。配额、幂等和状态转换在账户行锁保护
的事务内进行；CPU 计算期间不持有事务。挖掘租约独立于 PA 交互分析租约。

从仓库目录显式启动常驻进程：

```sh
uv run python -m pa_agent.web.mining_worker
# 验证用：最多领取一个任务后退出
uv run python -m pa_agent.web.mining_worker --once
```

Worker 与 Web 使用相同数据库和加密配置。本地默认使用 SQLite，生产使用持久
PostgreSQL。Vercel 网页函数不承担常驻 Worker；Worker 需单独部署到可常驻的
机器。没有在线 Worker 时任务保持排队，网页明确提示，不自动执行回退计算。

默认每 2 秒查询任务，每 5 秒续约，租约为 30 秒。每次领取产生新的随机租约
令牌；心跳、检查点、完成和失败写入均验证令牌及有效期。取消与成功写入在
同一状态机内串行化，已取消或超时任务不会发布成功产物。

候选完成后持久化进度和检查点；正常终止会释放任务等待恢复，异常中断由
租约过期触发恢复。未确认计算时间保守计入租约覆盖区间，不把租约过期后的
停机等待算作运行时间；恢复不重置已消耗预算。连续崩溃恢复最多允许三个执行
尝试，达到限制后失败。累计预算也包含输入准备及最终评估。取消和超时在有界
计算步骤之间检查，可能有一个步骤的响应延迟；超时结果会丢弃。

任务入队时固定词表、特征、搜索、回测版本和计算源文件内容摘要；Worker
执行前核验。版本不匹配时失败，避免按升级后的代码静默解释旧任务。升级后
需要重新提交新任务，并重新验证相应公式与样本外结果。
