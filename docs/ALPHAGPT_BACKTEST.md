# AlphaGPT 第二阶段：可复核的历史研究

计算实现：`pa_agent/web/research.py`。引擎版本为 **`pa-research-v1`**，因子版本
为 **`alphagpt-causal-v1`**。入口为
`run_research(chart: dict, config: ResearchConfig) -> dict`。

本引擎在用户选定的不可变 OHLCV 数据集上评估一条预先声明的规则。它不调用
大模型、不自动选择参数、不训练 AlphaGPT 公式、不连接交易账户，也不将研究
结果解释为未来收益预测。旧 AlphaGPT 已训练公式与本因子版本不兼容。

## 数据与市场假设

输入须有数据来源、标的描述、周期、采集时刻、数据集指纹和按时间升序排列的
300～5000 根已收盘 K 线，并明确声明 `market_kind="continuous_spot"`。
研究数据版本 `pa-research-ohlcv-v1` 使用专用规范化指纹校验；已有行情快照
使用其原有指纹口径，不能修改内容后继续沿用旧指纹。

首轮支持 Birdeye，以及声明连续现货假设的 CSV/模拟示例。CSV 的市场身份由
用户提供，不会因声明连续现货而获得“已核验的加密资产”身份。股票、期货等
依赖交易日历、涨跌停、合约乘数、展期或资金费用的市场不在本模型支持范围内。
支持 `1m/5m/15m/30m/1h/4h/1d` 固定周期，不支持周线或自然月线。

整个数据范围必须连续：重复、乱序、缺失周期、请求范围首尾缺失、未收盘数据、
坏价格或任意零/负成交量均拒绝生成研究结果。对零成交量采取整组拒绝，是为了
避免在无法确认可成交的 K 线上假定入场、退出或段末平仓。系统不补造行情，
不前向填充成交量，也不将当前流动性或 FDV 回填到过去。

数据指纹标识研究使用的市场输入和请求覆盖边界；采集时间和来源说明另行保留。
完整请求覆盖检查包括内部缺口及首尾缺失，不能悄悄缩短历史区间后继续回测。

## 配置与时间切分

| 字段 | 默认值 | 约束 |
|---|---|---|
| `factor` | `DEV` | `RET/PRESSURE/FOMO/DEV/VOL` 之一；LIQ 不可用 |
| `direction` | `below` | 低于阈值入场，或 `above` 高于阈值入场 |
| `entry_quantile` | `0.2` | [0,1]；below 时低于退出分位，above 时高于退出分位 |
| `exit_quantile` | `0.5` | [0,1] |
| `train_fraction` | `0.6` | [0.1,0.8] |
| `validation_fraction` | `0.2` | [0.1,0.8]，测试部分至少保留 0.1 |
| `initial_capital` | `10000` | 有限正数，最多 1e9，单位为数据集报价币种 |
| `fee_bps` | `10` | 每笔成交名义金额手续费，[0,500] 基点 |
| `slippage_bps` | `10` | 每次成交不利方向固定滑点，[0,500] 基点 |

多余配置项和非有限数被拒绝。训练条数取 `floor(N × train_fraction)`，验证
条数取 `floor(N × validation_fraction)`，剩余数据为测试段。训练至少 120 根，
验证和测试各至少 60 根；不满足时拒绝评估。

因子由共享的因果适配器计算，每根的归一化只使用当前与过去数据。验证/测试
开头可以使用此前历史作为滚动因子上下文，但不会继承前段仓位、现金余额或
交易信号。只有训练段内至少 60 个有效归一化值用于校准入场和退出阈值：

```text
entry = linear_quantile(训练段有效 normalized 值, entry_quantile)
exit  = linear_quantile(训练段有效 normalized 值, exit_quantile)
```

线性分位数在排序数组的 `(n-1) × q` 位置插值。阈值校准后冻结，验证和测试
数据不参与拟合、填补样本或选优。两阈值重合时拒绝运行，防止恒定因子产生
缺乏意义的反复交易。

训练段指标明确标记为 **`in_sample_calibration`**：阈值使用整个训练段拟合，
所以其收益不能被视为逐时可得的样本外结果。验证与测试分别为
**`out_of_sample`**，各自单独汇报。反复查看样本外结果后人工调整参数仍会
造成选择偏差；本系统不会把这种反复试验自动变成可靠证据。

## 信号与成交时序

每段从初始资金和空仓开始。对于 `below`，已收盘因子小于等于入场阈值时
产生买入信号，大于等于退出阈值时产生退出信号；`above` 使用相反方向。
交易只有“全部现金”和“100% 多头”两种状态，不加杠杆、不做空、不加仓。

第 `t` 根收盘后产生的信号，按第 `t+1` 根 **开盘价** 执行。分段第一根只
能产生供第二根使用的信号；分段之前的信号不会带入新段。预热时没有有效
因子值则不产生信号。

每段最后一根收盘时，若仍有持仓，按事先约定的研究期限强制平仓，并记录
`reason="segment_end"`。这不是根据最后一根价格作出的额外信号。最后一根
开盘可以执行前一根的入场信号，再在该根收盘按期限退出，两笔均计成本。

令 `f=fee_bps/10000`，`s=slippage_bps/10000`：

```text
买入价格 = 参考开盘价 × (1+s)
买入数量 = 现金 / (买入价格 × (1+f))
买入手续费 = 数量 × 买入价格 × f

卖出价格 = 参考价格 × (1-s)
卖出手续费 = 数量 × 卖出价格 × f
卖出后现金 = 原现金 + 数量 × 卖出价格 - 卖出手续费

滑点成本 = 数量 × abs(成交价格 - 参考价格)
完成交易 pnl = 退出净回款 - 该次入场前投入现金
```

普通卖出的参考价是下一根开盘价，段末强制平仓参考价是最后收盘价。允许
可分割数量，不模拟最小订单、订单簿深度、部分成交、链上 gas、税费或容量
限制。即使某根有成交量，也不能仅凭 OHLCV 保证全额成交，因此费用/滑点是
情景假设而非实际成交证明。

## 权益、指标与基准

每根收盘权益为 `cash + quantity × close`；最后一根使用扣除平仓成本后的
现金。权益必须始终为有限正数，无法可靠计算的极端数值范围会被拒绝。
权益曲线每根一条，时间为该根结束时刻的 UTC 秒。初始资金虽然单独存在于
指标中，也参与峰值初始化，所以即使第一笔亏损只有费用也会计入回撤。

| 指标 | 定义 |
|---|---|
| `total_return` | `ending_equity / initial_capital - 1` |
| `max_drawdown` | `max(1 - equity / 历史权益峰值)`，峰值初值为初始资金 |
| `net_pnl` | `ending_equity - initial_capital` |
| `fees` | 全部实际执行的买卖手续费之和 |
| `slippage_cost` | 全部买卖相对参考价的不利差额之和 |
| `closed_trades` | 完整买入/卖出配对的数量，包括段末平仓 |
| `win_rate` | 净 pnl 大于零的已完成交易比例；没有交易则为 `null` |
| `exposure` | 开盘处理后、收盘平仓前持有仓位的 K 线数量 / 本段总根数 |
| `benchmark_return` | 使用相同成本和研究窗口的买入持有收益 |

收益、回撤、胜率、持仓比例都采用**比例小数**：`0.05` 表示 5%。权益曲线的
`drawdown` 与 `max_drawdown` 都是非负数。现金金额不年化，不输出没有明确
日历依据的年化收益或 Sharpe。回撤只按收盘权益观察，不能当作盘中最大回撤。

买入持有基准同样在每段第二根开盘投入全部初始现金，最后一根收盘退出，并
计入相同费用与滑点。它与策略采用相同窗口，分别输出完整账本和指标，不使用
无成本基准与有成本策略混比。

仅计算预先约定的 **0×、1×、2×** 手续费/滑点情景；因子、阈值和交易时点
保持不变，输出训练、验证和测试各自收益及基准收益。这是成本敏感性分析，
不从三个情景中挑选“最佳配置”。

## 可审计输出与验证

结果保留引擎/特征版本、完整配置、数据指纹、训练阈值及样本数量、每段索引
范围、权益曲线、策略账本、基准账本、成本情景与限制说明。`split` 中 `end`
和 `end_exclusive` 均为不包含该索引的右边界。

每条成交记录包含执行时间 `time`、信号所在 K 线的**开盘时间**
`signal_time`、信号实际可知的收盘时间 `signal_at`、全局 K 线索引、参考价、
成交价、数量、费用、滑点成本、剩余现金和仓位，以及退出净 pnl。基准入场
和段末退出是预设规则，信号时间为空。下一根开盘通常与上一根收盘同一时刻，
因此用 `signal_bar_index + 1 == bar_index` 核验执行延迟更准确。

验证包含已知买卖算术、下一根开盘成交、费用与账本对账、初始资金基线回撤、
段末平仓、分段空仓、不使用样本外校准、改写测试段不改变训练阈值或验证曲线、
固定费用情景、无交易指标、常量因子拒绝、周期/成交量/数据指纹与请求覆盖
拒绝、配置边界及严格 JSON 序列化。这些检查保证实现口径和可复现性，不保证
该规则具有投资优势。

## 网页接口与存储

`POST /api/research/datasets` 接受四选一的 `data`（CSV）、`history`（Birdeye）、
`snapshot_id`（另须声明 `market_kind`）或 `demo:true`。研究导入单独使用 2.5 MB
请求体上限，CSV 内容上限为 2 MB；其他接口仍为 600 KB。Birdeye 时间为对齐的
UTC 秒区间 `[start,end)`，最多 25 次 HTTP 尝试、共享 60 秒截止时间，只用当前
账户保存的 Key。此适配器不会用服务端环境 Key 兜底。

`POST /api/research/runs` 接受 `dataset_id` 和 `config`。数据集与运行记录分别
提供账户内列表、删除接口，`GET /api/research/runs/{id}` 仅读取冻结结果，
`GET /api/research/runs/{id}/export` 下载结果及原始数据 `data`，不会重新计算。
`GET /api/research/demo` 提供公开的固定模拟 CSV 下载模板。

`web_research_datasets` 与 `web_research_runs` 为新增表，不改写已有账户和分析。
账户内相同内容数据集去重；每账户最多 20 个数据集、100 份记录，配额与引用检查
在事务内锁定账户行。运行记录使用账户/数据集组合外键；被引用的数据集无法
删除。所有私有接口沿用 Cookie 身份、CSRF 校验、跨标签页账户检查和账户租约。
保存的结果不随代码更新重算；独立复算需要相应版本引擎与导出的配置、数据。
