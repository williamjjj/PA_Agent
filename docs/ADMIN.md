# 管理员与邀请码

管理员使用独立账户，在普通登录页面登录。管理权限只用于站点邀请码管理，
不会获得其他用户的模型密钥、分析记录或研究数据。

## 首次创建管理员

在部署的私密环境变量中同时配置：

| 变量 | 要求 |
|---|---|
| `PA_WEB_ADMIN_USERNAME` | 独立用户名，3–40 位英文字母、数字、下划线、点或连字符，例如 `pa_admin` |
| `PA_WEB_ADMIN_PASSWORD` | 随机生成的初始密码，12–128 个字符；Vercel 中使用 Sensitive 类型 |

重新部署后首次初始化数据库时，服务会原子创建该管理员。管理员不需要邀请码。
若这个用户名已属于普通账户，初始化会拒绝创建；请改用未占用的管理员用户名。
不会根据用户名自动提升现有账户，也不会将第一个注册用户设为管理员。

管理员创建成功后，重启、重新部署或修改这两个变量都不会重置管理员密码。
登录后使用「个人设置」中的修改密码功能更换初始密码，并妥善保管新密码。
确认能够登录后，可从部署设置中移除初始密码变量；已有管理员仍保存在数据库。
目前没有邮件找回密码功能，修改环境变量不是密码恢复方式。

## 管理与发放

管理员登录后打开「邀请码管理」，可以查看、复制、手动修改或随机生成当前
邀请码，也可以关闭注册。新邀请码至少 12 个字符，最多 256 个字符。

- 复制当前邀请码后，通过自己的渠道发给受邀用户。
- 同一时间只有一个有效的共享邀请码，可供多位用户注册。
- 保存新码或重新生成后，之前发出的旧码立即失效；已注册账户不受影响。
- 停用注册后，任何邀请码都不能创建新用户；再次启用可继续使用保存的码。

管理接口在服务端逐次检查管理员身份。普通账户看不到管理入口，也无法通过
直接调用 API 修改邀请码。退出或切换账户时，页面会清除管理员界面中的邀请码。

## 升级已有数据库

首次运行这个版本时，现有 `PA_WEB_INVITE_CODE` 与 `PA_WEB_REGISTRATION`
会导入数据库，保留当时的注册行为。以后注册策略以数据库为准；更改环境变量
或重新部署不会覆盖管理员的设置，也不会重新启用已经撤销的邀请码。

新增的管理表自动创建，已有用户和加密数据不变。务必保持原来的
`PA_WEB_ENCRYPTION_KEY`，数据库里的邀请码也使用这把密钥加密。

Vercel 的 Preview 与 Production 只有在使用不同数据库时才拥有独立的账号和
邀请码配置。同一个数据库的所有新版部署共享同一策略。升级后请使用最新分支
地址；仍运行旧代码的历史部署没有数据库策略校验，必要时在 Vercel 中保护或
停用旧部署，避免用户继续通过旧版本注册。
